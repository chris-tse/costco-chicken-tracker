## PostgreSQL fixture

The acceptance jobs used an isolated, resettable `postgres:17-alpine` fixture. The Chrome artifact
records **PostgreSQL 17.10** for both Chrome runs; no production or personal database was used. The
fixture includes the deterministic historical sighting used by the journey. The workflow's test job
also passed against its PostgreSQL `17-alpine` service.

The physical beta-Safari run used the separately created
`chicken_tracking_acceptance_final` database in a persistent local `postgres:17-alpine` container,
resolved as **PostgreSQL 17.11**. The app image was built from candidate
`438fdb87aa6b702edc7cf002c4c544e3c9663830`. No production or personal database was used.

## Physical iPhone 15 Pro beta-Safari evidence

- **Device/browser:** iPhone 15 Pro in portrait; iOS 27.0 beta; Safari bundled with that OS.
  Tested 2026-08-14 in `America/Chicago`. The exact CSS viewport width was not instrumented, so
  this records the actual device constraint rather than claiming a 375px, 390px, or 430px width.
- **Journey:** Pass for Capture, reload before enrichment, successful doneness, correction, Cancel,
  confirmed deletion, Recent Sightings, and Plan empty/sparse states.
- **Failure and recovery:** Pass. PostgreSQL was stopped before selecting doneness. Safari showed
  the retryable failure within the bounded wait while preserving the label time. After PostgreSQL
  restarted, direct row checks immediately and after six additional seconds showed `doneness` still
  `NULL` and an unchanged `updated_at`, proving the timed-out request did not write later.
- **Accessibility/usability:** The journey remained fully functional in portrait with no reported
  horizontal overflow, obscured controls, unusable targets, focus/keyboard failure, or missing
  status feedback. Automated keyboard, focus, semantic, target, contrast, and overflow evidence
  remains in the Chrome acceptance artifact above.
- **Non-blocking design observations:** The outside-store-hours state is visually understated; the
  full-size Clear doneness control reads like a fourth radio-style doneness choice instead of a
  secondary reset action; and the Plan summary sentence feels detached from the weekday/time
  controls rather than composing them into an integrated phrase. These did not impede completion.
- **Accepted deviation:** iOS 27.0 was a beta channel. The product owner accepted this successful
  physical Safari run as sufficient for the private MVP without representing it as stable Safari.
